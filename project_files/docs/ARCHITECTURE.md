# Архитектура сервиса пропусков ЗТЗ

## Контекст и границы

Сервис решает один поток: водитель передаёт номер автомобиля, авторизованный сотрудник получает его и обрабатывает. Он не вызывает внешние API, не зависит от облачной авторизации и не разделяет код/данные с «Пульс ЗТЗ».

## Компоненты

```text
Браузер водителя/сотрудника
          │ HTTP / SSE
          ▼
frontend: Nginx :8080
  ├─ статический UI ru/tg + light/dark
  └─ reverse proxy /api/*
          │
          ▼
backend: FastAPI :8000
  ├─ RBAC + сессии + CSRF
  ├─ фильтры, пагинация, soft hide
  ├─ SSE broker
  └─ SVG QR generator
```

Frontend и backend — независимые Docker-образы. Backend не публикует порт на хосте в Compose и доступен только frontend-контейнеру.

## Почему SSE

Server-Sent Events подходят, потому что поток односторонний: сервер уведомляет кабинеты о создании или изменении записи. SSE работает поверх обычного HTTP, автоматически переподключается в браузере и проще WebSocket для этого сценария.

SSE-событие не переносит весь список. Оно сообщает, что данные изменились, после чего клиент повторяет обычный paginated GET с текущими фильтрами. Поэтому:

- reconnect не приводит к потере состояния — при открытии кабинет уже получает свежий список;
- права и фильтры остаются в одном HTTP endpoint;
- в резерве кабинет обновляет список раз в 30 секунд.

Ограничение: broker in-memory подходит для одной реплики backend. Для горизонтального масштабирования нужен общий event bus.

## Авторизация и безопасность

- Пароли хэшируются Argon2id; открытый пароль не хранится.
- После входа создаётся случайная сессия. На сервере хранится SHA-256 хэш токена, в браузере — только HttpOnly cookie `ztz_session` с `SameSite=Strict`.
- Изменяющие авторизованные запросы требуют отдельный CSRF-токен в заголовке.
- Middleware отклоняет небезопасные запросы с чужим `Origin`; CORS не включён.
- Login и публичная отправка имеют локальный sliding-window rate limit.
- Nginx добавляет CSP, запрет iframe, MIME sniffing и ограничение browser permissions.
- API проверяет роль независимо от UI. Логист всегда получает условие `is_hidden = false`, даже если вручную передаст `visibility=all`.
- Физического DELETE endpoint для заявок нет.
- Создание и смена пароля пользователя доступны только администратору с CSRF-защитой; пароль проверяется по минимальной политике, сразу хэшируется Argon2id и никогда не возвращается API. При смене пароля все активные сессии пользователя отзываются.
- Мягкое отключение меняет `users.is_active`, сохраняет запись для аудита/восстановления и в той же транзакции удаляет все её сессии. Login и каждый API-запрос дополнительно проверяют `is_active`; открытый SSE-поток получает сигнал, перепроверяет сессию и завершается.
- Администратор не может отключить собственную активную учётную запись или последнего активного администратора.

Для production обязательно включить TLS и `COOKIE_SECURE=true`, заменить demo credentials, ограничить доверенные proxy и добавить управляемую ротацию секретов.

## Миграции и инициализация

Каждый запуск backend выполняет `alembic upgrade head`, затем идемпотентный seed двух демонстрационных пользователей. Seed создаёт только отсутствующие записи и не перезаписывает существующие пароли.

## Локализация и темы

UI-тексты находятся в едином словаре `frontend/assets/js/i18n.js`, ключи `ru` и `tg` имеют одинаковую структуру. Язык сохраняется в `localStorage`.

Тема задаётся атрибутом `data-theme` на `<html>`. CSS использует семантические color tokens. Если сохранённого выбора нет, берётся `prefers-color-scheme`; ручное переключение сохраняет `light` или `dark` в `localStorage` и действует на всех страницах.

## Упаковка и будущая доставка

`compose.yaml` — единственный обязательный deployment manifest на текущем этапе. Образы не содержат интеграций с Harbor, Portainer или Infisical, но разделены так, чтобы backend-разработчик мог:

1. собрать/tag/push frontend и backend в Harbor;
2. перенести Compose/Stack в Portainer;
3. заменить локальные environment values ссылками/инъекцией из Infisical;
4. подключить внешний TLS reverse proxy и резервное копирование persistent volume.
