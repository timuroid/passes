# Сервис пропусков ЗТЗ

Независимый сервис для передачи номера автомобиля от водителя логисту и последующего оформления пропуска. Водителю не нужны регистрация, логин или пароль. Сотрудники работают в защищённом ролевом кабинете.

Проект не связан с соседним проектом `Пульс_ЗТЗ` и не изменяет его файлы или данные.

## Что реализовано

- полноэкранная страница водительского киоска с обязательными номером автомобиля, телефоном и кнопкой отправки;
- управляемые приложением панели ввода и встроенная touch-клавиатура с полным латинским алфавитом для номера и отдельным цифровым набором для телефона: системная экранная клавиатура киоска не вызывается, физическая клавиатура поддерживается;
- вход по логину и паролю для логиста и администратора;
- список транспортных средств с фильтрами по датам и номеру, сортировкой, пагинацией и размером страницы 10/25/50/100; поиск номера не зависит от визуально совпадающих кириллических и латинских букв;
- выгрузка всех записей, соответствующих выбранным фильтрам, в Excel;
- realtime-обновление через Server-Sent Events (SSE) и резервное обновление раз в 30 секунд;
- мягкое скрытие/восстановление транспортных записей логистом и администратором;
- отдельный список, безопасное создание и мягкое отключение/восстановление пользователей только для администратора;
- крупный переключатель шести языков водительского киоска: русский, таджикский, узбекский, казахский, кыргызский и азербайджанский; кабинет сотрудников фиксированно работает на русском языке;
- личное переключение светлой и тёмной темы в кабинете сотрудников и отдельная административная настройка общей темы водительского киоска;
- Alembic-миграции, healthchecks, backend-тесты и сквозной smoke-тест;
- отдельные образы frontend и backend для последующей доставки через Harbor/Portainer и подстановки секретов через Infisical. Интеграции с этими системами намеренно нет.

## Запуск одной командой

Нужны только Docker и Docker Compose. Из корня проекта:

```bash
docker compose up --build -d
```

После прохождения healthchecks:

- страница водителя: <http://localhost:18080/>
- вход сотрудников: <http://localhost:18080/login>
- интерактивная документация API: <http://localhost:18080/api/docs>

Проверить состояние:

```bash
docker compose ps
```

Остановить контейнеры, сохранив данные:

```bash
docker compose down
```

Удаление volume командой `docker compose down -v` необратимо удалит сохранённые данные и не должно выполняться без осознанного решения.

## Демонстрационные учётные записи

Значения предназначены только для локального запуска и открыто заданы в `compose.yaml`/`.env.example`:

| Роль | Логин | Пароль |
|---|---|---|
| Логист | `logist` | `Logist-Local-2026!` |
| Администратор | `admin` | `Admin-Local-2026!` |

При первом старте backend создаёт отсутствующих пользователей. Повторный старт не меняет пароль уже существующей записи. Для другого локального набора скопируйте `.env.example` в `.env` и измените значения до первого запуска.

Это не production-секреты. Перед реальным развёртыванием нужно отключить demo-seed или передавать уникальные значения через защищённое хранилище, включить HTTPS и `COOKIE_SECURE=true`.

## Роли и сценарии

### Водитель

1. Подходит к терминалу с уже открытой страницей `/`.
2. Вводит номер автомобиля и телефон встроенной экранной клавиатурой, затем нажимает «Отправить».
3. Получает подтверждение. Учётная запись не создаётся.

### Логист

1. Входит на `/login`.
2. По умолчанию видит активные записи и может отдельным фильтром открыть скрытые или все.
3. Фильтрует по датам/номеру, выбирает порядок и размер страницы.
4. Скрывает обработанную запись или восстанавливает её.
5. При необходимости выгружает отфильтрованный список в Excel.
6. Получает новые номера через SSE без ручного обновления.

### Администратор

1. Имеет те же возможности работы с транспортом, что и логист.
2. Открывает вкладку пользователей, создаёт учётные записи с ролью логиста или администратора, меняет пароли, мягко отключает и восстанавливает пользователей.
3. Во вкладке «Настройки» выбирает светлую или тёмную тему для всех водительских киосков. На самой водительской странице переключателя нет.

Отключённый пользователь остаётся в списке, сразу теряет активные сессии и не может войти до восстановления. Текущий администратор не может отключить себя; backend также защищает последнего активного администратора.

## Тестирование

Backend-тесты запускаются внутри одноразового контейнера:

```bash
docker compose run --rm backend pytest -q
```

Smoke-тест выполняется на уже поднятом стеке и проверяет цепочку «водитель → логист → скрытие → восстановление → создание пользователя → отключение → отказ во входе → восстановление → успешный вход»:

```bash
docker compose exec -T backend python scripts/smoke_test.py http://127.0.0.1:8000
```

Smoke-тест создаёт одну диагностическую заявку с латинским номером `AA…C` и одного пользователя с префиксом `smoke`. Сценарий дополнительно подтверждает поиск этого номера кириллическими визуальными аналогами. Пользователь проходит отключение/восстановление и остаётся активным после подтверждённого повторного входа.

## Архитектура

- `frontend`: Nginx Unprivileged, статические HTML/CSS/JavaScript, обратный proxy `/api/*`.
- `backend`: FastAPI + SQLAlchemy + Alembic, сессионная RBAC-авторизация, SSE и формирование Excel-файлов.

Подробнее: [project_files/docs/ARCHITECTURE.md](project_files/docs/ARCHITECTURE.md). Описание HTTP-интерфейса: [project_files/docs/API.md](project_files/docs/API.md).

## Ограничения и дальнейшие шаги

- Сервис рассчитан на один backend-инстанс: SSE-broker хранится в памяти. Для нескольких реплик нужен общий event bus, например Redis или NATS.
- In-memory rate limit сбрасывается при рестарте и не координируется между репликами.
- Переводы водительской страницы на языки кроме русского перед production требуют редакторской проверки носителями.
- Администратор может создавать пользователей, менять им пароли и мягко отключать/восстанавливать учётные записи.
- Нет журнала всех смен видимости: хранится текущее состояние и отметки последнего скрытия/восстановления.
- Для production нужны TLS, закрытая сеть сервисов, уникальные секреты, резервное копирование, централизованные логи и наблюдаемость.
