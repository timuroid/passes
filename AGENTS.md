# Правила проекта «Сервис пропусков ЗТЗ»

- Основной язык документации, интерфейса и рабочих отчётов — русский.
- Пользовательский интерфейс должен сохранять i18n-архитектуру и поддержку таджикской локализации как обязательное требование; новые тексты добавляются одновременно в словари `ru` и `tg`.
- Единственный обязательный способ локального запуска и упаковки — Docker Compose. Не добавлять обязательные локальные зависимости кроме Docker с Compose.
- Frontend и backend собираются как самостоятельные контейнеры, пригодные для последующей доставки backend-разработчиком через Portainer/Harbor/Infisical. Интеграцию с этими системами в этом проекте не выполнять.
- Не использовать внешние API и не добавлять реальные секреты. Локальные демонстрационные учётные данные должны быть явно помечены и задокументированы.
- Авторизация должна оставаться ролевой: `logist` и `admin`. Скрытие заявок — только мягкое, без физического удаления.
- Для изменений backend поддерживать автоматические тесты; для ключевого бизнес-потока поддерживать воспроизводимый smoke-тест.
- Не выполнять коммиты, push и внешние публикации без отдельной просьбы.
- Не создавать и не изменять материалы в `Работа/IntBiS/02_Общая докементация/spec/` без явного разрешения.
- Не вмешиваться в соседний проект `Пульс_ЗТЗ`.
- Значимые решения, структурные изменения и итоговые передачи фиксировать в `CHANGE_HISTORY.md`.
